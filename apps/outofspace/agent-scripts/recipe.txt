# The furnace's two modes: cook a list, or run one reaction to a stated conversion.
#
# A recipe furnace and a general one are not two machines. They share both dials a furnace already
# had -- a temperature and a residence time -- and differ only in what they are being asked, so this
# is one machine with a mode rather than a second kind on the build menu.
#
# ⛔ **What makes the split principled: a completion percentage only has a referent when there is
# exactly ONE reaction to be complete.** A broad kiln whitelisted to serpentine, ammonia and hematite
# is running three conversions at once and "95% done" names nothing -- so broad mode states a
# duration, and recipe mode states a percentage. The dials differ because the question differs.
#
# What to read in the shots:
#   `broad`   -- the general furnace, unchanged and still the default. HOLD AT / FOR / FEED LIST, and
#                COOKING says how many species the player named. This is every furnace in every save.
#   `cracking`  -- one press of MODE, which lands on the first row in the table: ammonia cracking, a
#                  SINGLE-reagent reaction. The control surface has SWAPPED -- RUNS and UNTIL replace
#                  the two dials, HOLDS AT is a readout rather than a button, and the FEED LIST
#                  button is gone because a recipe IS a feed list. ⚠️ **RUNS names what it CONSUMES**
#                  (`Reaction.principal`); what comes out is on YIELDS, and there is no TAKES row
#                  because a one-reagent row would only repeat the button.
#   `reduction` -- stepped on to ferrosilite reduction, which is the case the whole plan was written
#                  against. Now TAKES appears -- FERROSILITE + CARBON, the two the network will route
#                  here and the two the kiln will meter into a charge. ⚠️ **1250 K is the lowest rung
#                  ABOVE the 1200 K onset**, never the onset itself: a reaction at its onset runs at
#                  BASE_RATE and essentially nothing happens.
new
creative 1

brush FURNACE right
material Forsterite
place 24 14
landmarks

inspect furnace furnace DECK
shot broad

# Into recipe mode. The first rung off "broad" is the first row of REACTIONS, so this walks the
# whole table in the order it is written -- there is no curated list to keep in step.
tune furnace furnace recipe
inspect furnace furnace DECK
shot cracking

# On to ferrosilite reduction. ⚠️ The rung number is the table's, not a designed position, which is
# the cost of deriving the ladder rather than writing one out.
tune furnace furnace recipe 21
inspect furnace furnace DECK
shot reduction

# ── The picker ───────────────────────────────────────────────────────────────────────────────────
#
# ⛔ **A sheet, not a cycling button.** One row per reaction is a list whose length is the
# chemistry's, and stepping forty-five rungs to reach the one you want is not a control.
#
#   `sheet` -- the picker. BROAD is the first row and is always offered: it is the other half of the
#              machine, not an escape from the list. Every other row is a reaction this vessel could
#              actually run right now -- ⚠️ **filtered by what is aboard PURE**, so a starter vessel
#              holding only iron shows very little. The column beside each is the temperature it
#              would be held at, which is the cost of running it, and the dim line under each row is
#              the whole reaction: what goes in on the left, what comes out on the right.
#              ⛔ **The row that is already set never disappears**, even once its reagents are spent
#              -- the whitelist sheet's rule, and for its reason: losing the row would take away the
#              only control that could change it.
# ⚠️ **`RUNS` and not `MODE`.** `tapLabel` falls back to a substring match, and "MODE" is also in
# "BUILD MODE" on the top bar -- tapping that put the harness into FLIGHT MODE and shot a panel that
# was never opened. Both buttons open the picker; this is the one whose label is unique on screen.
tap RUNS
shot sheet

# Nothing is plumbed to it, so the kiln states an appetite and waits -- which is the correct idle
# state for a demand network and not a stall.
expect massBalance = 0
